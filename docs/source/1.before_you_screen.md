## OPS Data Collection

### Data Structure

During a brieflow run, microscope files are loaded from dataframes (the SBS and phenotype sample tables) that give each file's path and metadata ({term}`plate <Plate>`, {term}`well <Well>`, {term}`tile <Tile>`, {term}`cycle <Cycle>`, and so on).
The paths and metadata are parsed from a data directory with a regular expression.
The preprocess notebook, [`analysis/0_preprocess.py`](https://github.com/cheeseman-lab/brieflow-analysis/blob/marimo/analysis/0_preprocess.py), builds these tables and explains the options.

Brieflow reads Nikon `.nd2`, Imaris `.ims` and `.tiff` files.
A file can hold one tile (`SBS_DATA_ORGANIZATION` or `PHENOTYPE_DATA_ORGANIZATION` set to `"tile"`) or a whole well (`"well"`); a well file with a single position is read as one tile.
TIFF inputs usually need an external metadata file for stage positions, and z-planes split across files can be max-projected on conversion.

The file patterns can describe other layouts, but the notebooks, the small test and
[brieflow-auto](brieflow_auto.md) all expect the one below, and brieflow-auto refuses to start on
data that does not follow it. Save the raw data outside the brieflow-analysis directory, in
a protected location, so inputs stay separate from outputs.

#### Hierarchical Structure

One directory per modality, then one per plate, then one per SBS cycle or phenotype round:

```
<data root>/
├── input_sbs/                 SBS_IMAGES_DIR_FP (screen.yaml data.input_sbs_dir)
│   ├── plate_1/
│   │   ├── c1/                one directory per sequencing cycle
│   │   ├── c2/
│   │   └── ...
│   └── plate_2/ ...           plates numbered 1..P, no gaps
└── input_ph/                  PHENOTYPE_IMAGES_DIR_FP (screen.yaml data.input_phenotype_dir)
    ├── plate_1/
    │   ├── round_1/           one directory per phenotype imaging round
    │   ├── round_2/           multi-round screens only
    │   └── ...
    └── plate_2/ ...
```

Rules:

- The cycle and round come from the directory, never from the file name. Files from different
  cycles saved in one folder have to be split into `c<M>/` directories first.
- One acquisition per cycle or round directory. A vendor subfolder such as `Images/` (Opera
  Phenix) is fine; two exports of the same fields in one directory are not.
- Every plate has the same phenotype rounds, and every round images the same wells and
  fields. Round numbers follow acquisition order.
- A single-round screen still uses `round_1/`.

#### SBS (Sequencing) Files

- Files sit in their cycle directory (`c1`, `c2`, ...).
- File names carry the well and tile (and the plate, if it helps you); include the channel when
  each file holds a single channel.
- Extra cycles or channels that help segment cells can be included; the preprocess and SBS
  modules have options for them.

**Example SBS file:** `<data root>/input_sbs/plate_1/c2/P001_Wells-A3_Points-214.nd2`

#### Phenotype Files

- Files sit in their round directory (`round_1`, `round_2`, ...).
- File names carry the well and tile; include the channel when each file holds a single channel.
- With several rounds, each round directory holds only the channels imaged in that pass. The
  rounds are read in order and their channels concatenated, so list the phenotype channels
  round by round (round 1 first) wherever the channel order is set.

**Example phenotype file:** `<data root>/input_ph/plate_1/round_1/P001_Wells-B1_Points-585.nd2`

#### Alignment Verification

**Critical Quality Control Step:** Check alignment between:
- Rounds of phenotyping data (`round_1` vs. `round_2` vs. …)  
- Cycles of sequencing data for each cycle (`c1` vs. `c2` vs. …)

Alignment verification should be performed before proceeding with downstream analysis. Downstream analysis will be impossible with large spatial shifts in alignment.
